# Build every geometry through GeoPointFactory — a raw NTS factory gives you SRID 0

Every geometry column in this schema is **SRID 4326** (WGS84). NetTopologySuite's default
factory produces SRID **0**, and nothing in the type system objects — so the danger is a
call site that constructs geometry itself.

There is exactly one place that knows the SRID and the coordinate order, and it is the only
correct way in — for **paths as well as points**, since `PathGeometrySrid4326` pinned
`Trail.GeoPath`, `Hike.GeoPath` and `TrailImportProposal.FeatureGeometry` too:

```csharp
// backend/Core/Common/GeoPointFactory.cs
GeoPointFactory.FromLonLat(longitude, latitude)      // Point, SRID 4326
GeoPointFactory.FromLonLatPath(lonLatCoordinates)    // LineString, SRID 4326
GeoPointFactory.ToLatitude(point)                    // decimal? back out
GeoPointFactory.ToLongitude(point)
```

`FromLonLatPath` is total: it builds the empty line too (the hike seeds rely on that), and
lets NetTopologySuite's throw on *exactly one* point through, because every caller already
decides what a degenerate path means. The one place that must **not** use it is
`LocalMetricProjection.Project(LineString)`, whose coordinates are metres on a flat plane.

`Geometry.DefaultFactory.WithSRID(...)` appears **once in the whole backend**, inside that
file. If a diff adds a second one, that is the finding: services, repositories, factories,
importers and the test `Utilities` all go through `GeoPointFactory`, including
`TrailRepository`'s proximity ranking and `FacilityImporter`.

## Why it is worth centralising rather than remembering

Two things silently disagree if a call site gets it wrong, and they disagree in *opposite*
directions, so the same omission can be green on one path and red on the other:

- **PostGIS** refuses a mixed-SRID operation, or computes a distance in degrees.
- **SpatiaLite** (the test provider) enforces the column's SRID on insert, so it surfaces
  as a *test* failure about geometry rather than a wrong answer.

But only for a *write*. SpatiaLite computes `ST_Distance` across mismatched SRIDs without
complaint where PostGIS raises, so a mixed-SRID **query** is invisible to the whole suite —
see [[postgis-srid-coercion]] for that and for why a retag `UPDATE` is the wrong fix.

And `new Coordinate(x, y)` is **(longitude, latitude)** — X is longitude — while the wire
contracts carry `{ latitude, longitude }`. Reversing it is silent and puts things in the
Gulf of Guinea. `GeoPointFactory`'s naming (`FromLonLat`) exists to make the order
unmissable at the call site.

## Lat/long travel as a pair

`Facility.Coordinates` and `TrailObstacle.IncidentLocation` are both `Point?` — nullable by
design (an area facility has no point; a reporter may not pin one). A **half** pair is not a
location: the request validators reject one ordinate without the other, and
`FacilityService.UpdateFacilityAsync` rebuilds the point only when both are supplied. A new
endpoint that accepts a lone latitude needs the both-or-neither validator rule, or it writes
a point at longitude 0.

the wire boundary; this note is only the trap.
