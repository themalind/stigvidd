# The app type check is green locally only because the gitignored expo-env.d.ts pulls in Node's types

`cd app && npm run typecheck` (`tsc --noEmit`) passed on a developer checkout and failed in
GitHub CI's `app` job with 34 errors:

```
src/api/__tests__/auth.test.ts(20,3): error TS2304: Cannot find name 'global'.
src/services/__tests__/logger.test.ts(173,77): error TS2345: Argument of type
  '(value: unknown) => void' is not assignable to parameter of type '() => void'.
```

`app/tsconfig.json` includes `expo-env.d.ts` and `.expo/types/**`. Both are **gitignored** and
generated by Expo the first time it runs, so they exist on every box that has started the app
and on no fresh clone. `expo-env.d.ts` is `/// <reference types="expo/types" />`, and that
brings in the Node typings. Without them, `compilerOptions.types` (`["jest", "geojson"]`)
leaves out Node's `global`, and `setImmediate` falls back to React Native's
`(callback: () => void)` signature, which rejects `new Promise((resolve) => setImmediate(resolve))`.

Measured 2026-09-15 by type-checking `src/**` with an otherwise identical config that omits
those two includes: exactly CI's 31 `TS2304` + 3 `TS2345`. Adding `"node"` to `types` took it to 0.
`@types/node` comes in transitively (via `jest-util`), so `npm ci` installs it.

**To reproduce CI locally**, move `expo-env.d.ts` and `.expo/` aside, or type-check with a
config that includes only `src/**`. A local green `tsc` says nothing about CI while those files exist.
